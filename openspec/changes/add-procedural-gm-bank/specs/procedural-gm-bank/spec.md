# Spec Delta

## Purpose

Provides a generated General MIDI bank that reproduces the Windows `gm.dls` (same instruments, regions, articulation and wave indices) from committed synthesis parameters, so GM-sampler songs sound the same on platforms without the OS bank and in the DAW, plus the tool that fits those parameters iteratively against the original.

## ADDED Requirements

### Requirement: Generated bank is a drop-in DLS
The generator SHALL produce a complete `RIFF 'DLS '` buffer that the existing bank reader parses. Every consumer that accepts bank bytes (song render, unisynth, WaveSabre Adultery, synth-wasm, the DAW) SHALL accept the generated bank without code changes.

#### Scenario: Reader accepts the generated bank
- **WHEN** the generated bank is parsed by the bank reader
- **THEN** parsing succeeds with 235 instruments and 495 waves

#### Scenario: Song plays on the generated bank
- **WHEN** a song that uses a GM.DLS instrument is rendered with the generated bank
- **THEN** it renders without error and the GM track is not silent

### Requirement: Structure matches the Windows bank
The generated bank SHALL carry the Windows `gm.dls` instrument list (drum flag, bank, program, name), regions (key range, velocity range, key group, wave index), articulation connections and `wsmp` (unity note, fine tune, gain, loop), and per-wave sample rate, length and loop, value for value.

#### Scenario: Structure diff is empty
- **WHEN** the bank fingerprint dump of the generated bank and of the Windows `gm.dls` are compared, ignoring bit depth
- **THEN** every `ins` and `wave` line is identical

#### Scenario: Wave index portability
- **WHEN** a song references pool wave N
- **THEN** the generated wave N has the same rate, length, unity note and loop as Windows wave N

### Requirement: Deterministic, target-independent output
Generation SHALL be a pure function of the committed parameters and SHALL produce byte-identical output on native (x86_64, aarch64, i686) and wasm32 builds. It SHALL NOT depend on platform math library transcendental functions.

#### Scenario: Native and wasm agree
- **WHEN** the bank is generated by a native build and by the wasm build
- **THEN** both buffers have the same length and the same hash

#### Scenario: Repeated generation
- **WHEN** the bank is generated twice in one process
- **THEN** both buffers are byte-identical

### Requirement: Synthesis models within a parameter budget
Each wave SHALL be the sum of at most 4 layers, each from a fixed model family (`additive` with harmonic table, `ks`, `modal`, `noise`, `drum`, `metal`, `shaker`, `fm`, `formant`, `subtractive`), described by at most 512 numbers in total including harmonic table entries. Parameters SHALL NOT contain sample data (waveform, residual or wavetable PCM).

#### Scenario: Budget exceeded
- **WHEN** a wave's parameter set holds more than 512 numbers or more than 4 layers
- **THEN** loading the parameters fails naming the wave and its count

#### Scenario: Unknown model family
- **WHEN** a layer names a family that is not in the fixed set
- **THEN** loading the parameters fails naming the wave and the family

#### Scenario: Fit respects the budget
- **WHEN** `gmfit fit` optimises a wave
- **THEN** the written parameter set is within the layer and number budget

### Requirement: Optional harmonic correction
A wave MAY carry one harmonic correction table: per-harmonic gains (dB, clamped to ±24 dB) relative to the wave's fundamental, applied to the sum of its layers. On the loop it SHALL act exactly per harmonic; on the attack as a smooth EQ through the same points. Its entries count toward the 512-number budget. A wave without the table SHALL render as the plain sum of its layers.

#### Scenario: Correction fixes loop timbre
- **WHEN** a `ks` wave whose loop has harmonic 3 at -6 dB relative to the original gets a correction table with +6 dB at harmonic 3
- **THEN** harmonic 3 of the generated loop matches the original within 0.1 dB and the other harmonics are unchanged

#### Scenario: Analytic correction
- **WHEN** `gmfit correct <wave>` runs
- **THEN** the table is computed from the original and model loop spectra without optimisation, clamped, truncated to the remaining budget, and written only if the score improves

#### Scenario: No table
- **WHEN** a wave has no correction table
- **THEN** its output equals the sum of its layers byte for byte

### Requirement: Optional time × band correction
A wave MAY carry one time × band correction table `tf` of dB gains (±24 dB) on a fixed grid of bands × time rows (design D4c). It SHALL shape the attack, or the whole unlooped wave, after the harmonic correction. A loop SHALL stay untouched, with the gains fading to 0 dB before the loop start. Its entries count toward the 512-number budget.

#### Scenario: Band gain lands
- **WHEN** a wave gets `tf` +6 dB on bands 8–12 and 0 dB elsewhere
- **THEN** band 10's energy rises by 6 ± 1 dB, band 1 moves less than 0.5 dB, and the loop samples are unchanged

#### Scenario: Analytic tf fit
- **WHEN** `gmfit correct <wave>` runs
- **THEN** after the harmonic table it sets each `tf` cell from the original − model band energy over the attack, over 4 passes, trims the harmonic table's tail if the budget needs room, and writes the result only if the score improves

### Requirement: Optional fine envelope correction
A wave MAY carry an `env` table of dB gains at fixed onset times (design D4d), applied per sample to the attack after the `tf` table. A loop SHALL stay untouched, with the gains fading to 0 dB before the loop start. Its entries count toward the 512-number budget.

#### Scenario: Flat envelope gain lands
- **WHEN** a looped wave gets an `env` table of -6 dB at every point after the first
- **THEN** the RMS level around each point from 4 ms on drops by 6 ± 0.1 dB and the loop samples are unchanged

#### Scenario: Ensemble spread loops exactly
- **WHEN** a looped `additive` sustain layer has `spread` 12 cents
- **THEN** the loop repeats within 1e-5 and harmonic 1 covers at least 3 loop-DFT bins within 10 dB of its peak

### Requirement: Every wave is generated
Every one of the 495 waves SHALL have a committed parameter set. A wave without parameters, or whose output is non-finite, silent or clipped, SHALL fail the generator's test suite rather than ship as silence.

#### Scenario: Missing parameters
- **WHEN** the parameter set of a wave is removed
- **THEN** the generator test suite fails naming that wave

#### Scenario: Output sanity
- **WHEN** the full bank is generated
- **THEN** every wave has finite samples, a peak above -40 dBFS and no sample at full scale for more than 4 consecutive samples

### Requirement: Seamless loops
For every looped wave, the generated signal SHALL be exactly periodic over the loop from the loop start on, so the wrap from loop end to loop start is an ordinary step of the signal and cannot click: rendering past the loop end SHALL reproduce the loop samples.

#### Scenario: Loop wrap
- **WHEN** a looped wave is rendered one loop length past its loop end
- **THEN** the extra samples equal the loop samples (within 1e-5) for every looped wave

### Requirement: Partial generation
The generator SHALL be able to build only a given set of wave indices. Waves outside the set SHALL keep their length and loop and contain silence, so indices and structure are unchanged.

#### Scenario: Subset for a song
- **WHEN** only waves 289–298 are requested
- **THEN** those waves equal the full-build waves byte for byte and all other waves are silent with unchanged length

### Requirement: Load-time budget
Generating the full bank SHALL take at most 300 ms single-threaded in a native release build and at most 1 s in the wasm build on the reference development machine (Apple silicon).

#### Scenario: Native timing
- **WHEN** the full bank is generated in a native release build on the reference machine
- **THEN** generation completes within 300 ms

### Requirement: Platform bank selection
Bank resolution SHALL follow one policy: on Windows the OS `gm.dls` when it exists and parses, otherwise the generated bank; on macOS and Linux the generated bank. An explicit choice (`proc`, `os`, or a file path) SHALL override the policy.

#### Scenario: Windows with OS bank
- **WHEN** the default policy runs on Windows and `%SystemRoot%\System32\drivers\gm.dls` parses
- **THEN** the OS bank is used

#### Scenario: Windows without OS bank
- **WHEN** the default policy runs on Windows and the OS file is absent or unparseable
- **THEN** the generated bank is used

#### Scenario: macOS
- **WHEN** the default policy runs on macOS
- **THEN** the generated bank is used even though `gs_instruments.dls` exists

#### Scenario: Song CLI override
- **WHEN** `song render <song> --bank proc` runs
- **THEN** the generated bank is used regardless of platform and `GM_DLS`

### Requirement: Similarity score
The fitting tool SHALL score a generated wave against the original wave of the same index with one number in [0, 1] (1 = identical), combining multi-resolution log-spectral distance, amplitude-envelope distance and loop-region distance, and SHALL report each component.

#### Scenario: Identical input
- **WHEN** the original wave is scored against itself
- **THEN** the score is 1.0 and every component distance is 0

#### Scenario: Silence
- **WHEN** a silent wave is scored against a non-silent original
- **THEN** the score is below 0.1

#### Scenario: Missing onset click is penalised
- **WHEN** a decaying 55 Hz body is scored against the same body plus a 2 ms broadband click
- **THEN** the onset distance `d_onset` (A-weighted spectrogram distance over the first 50 ms, frames centred from t = 0) is above 3 dB

#### Scenario: Loop shimmer is compared by depth
- **WHEN** two looped waves have the same loudness wobble depth but a different pattern
- **THEN** their envelope distance over the loop is below 0.4 dB, and a flat loop against the wobbling one is at least twice that

### Requirement: Render and compare report
`gmfit render <wave>` SHALL write the original and generated wave as WAV, a PNG contact sheet (waveforms, original vs generated spectrograms, difference), and a JSON report on stdout with wave index, instrument names using it, model layers, score, components and flags (`silent`, `clipped`, `nan`, `loop_click`, `pitch_off`, `env_off`).

#### Scenario: Report for a wave
- **WHEN** `gmfit render 289` runs with `GM_DLS` set
- **THEN** the WAV pair, the PNG and a JSON report with score and flags are produced and the exit code is 0

#### Scenario: No original bank
- **WHEN** `gmfit render` runs without `GM_DLS`
- **THEN** it exits non-zero with a message that the original bank is required

### Requirement: Iterative fit
`gmfit fit <wave>` SHALL start from an analysis of the original (pitch, partials, envelope, noise bands, loop) and optimise the wave's parameters to maximise the score, writing the parameters only when the score improves on the committed one, and SHALL be reproducible for a given seed.

#### Scenario: Improvement written
- **WHEN** a fit reaches a higher score than the committed one
- **THEN** the wave's parameter file and its committed score are updated

#### Scenario: No regression written
- **WHEN** a fit ends below the committed score
- **THEN** the committed parameters are left unchanged and the tool reports both scores

#### Scenario: Seeded reproducibility
- **WHEN** the same fit runs twice with the same seed and iteration count
- **THEN** both runs produce identical parameters

### Requirement: Parameter sweep
`gmfit sweep <wave> <param> <values>` SHALL render one variant per value and report each variant's score and flags with one contact sheet row per variant, without changing committed parameters.

#### Scenario: Sweep a decay time
- **WHEN** a sweep of one layer's decay over 5 values runs
- **THEN** 5 scored rows are reported and the committed files are unchanged

### Requirement: Whole-bank report and regression gate
`gmfit report` SHALL score every wave and list them by score with GM family. With `--check` it SHALL exit non-zero when any wave scores more than 0.005 below its committed score. Tests needing the original bank SHALL skip when `GM_DLS` is unset.

#### Scenario: Regression detected
- **WHEN** a generator change lowers wave 36's score by 0.02 and `gmfit report --check` runs
- **THEN** it exits non-zero naming wave 36 with old and new scores

#### Scenario: CI without the bank
- **WHEN** the test suite runs without `GM_DLS`
- **THEN** the score tests skip and the determinism, structure-shape and sanity tests still run
